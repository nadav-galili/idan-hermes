Cron vs per-session don't quite fit together. Cron is a timer (e.g. daily). "Per-session" is an event — it fires after a WhatsApp session goes quiet, which cron can't express. Both can still live on the Hermes box. Reconciliation: the job stays a standalone script on the box; Hermes fires it after a session ends (a debounced "session idle" hook) instead of a cron timer. A daily cron can stay as a cheap safety-net sweep.

Merge — my recommendation: regenerate the whole note

Best practice for a derived-from-a-source-of-truth layer (this is a "materialized view" over raw/):

  • Idempotent by construction — re-running on the same raw yields the same note, so a per-session job that re-touches a note never double-writes or drifts.
  • No dupe accumulation — append-only slowly grows contradictory/duplicate lines the model then has to fight; regenerate keeps each note clean.
  • Cost is fine at MVP scale — pass only the touched notes (not all of notes/) as context; notes are small. Revisit only if a note grows large.

Trade-off: slightly more tokens per run than a blind append. Worth it — correctness > a few tokens, and raw is always the safety net.
