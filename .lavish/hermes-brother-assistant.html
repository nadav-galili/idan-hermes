Risks & things to watch

WhatsApp ban risk. Unofficial libs can get a number flagged. Dedicated SIM contains the blast radius — never his real number. Use a physical SIM, not VoIP.
Session drops. QR sessions occasionally need a re-scan. Keep the SIM accessible; expect the odd re-link.
CPU headroom. Box already averages 51%. Monitor after launch; upgrade tier if it's steady, not spiky.
Reply identity. Sent emails come from the assistant's address, not his. "Send-as him" alias is a later add if he wants it.
Data privacy. His forwarded emails + WhatsApp live on your VPS. Fine for a brother, but backups now hold his data — hence the backup toggle.

✅ Resolved — Hermes has built-in scheduling

Confirmed in the Hermes docs: "Scheduled automations — Built-in cron with delivery to any platform," and the integrations page lists "scheduled reports" under WhatsApp. So Hermes can initiate WhatsApp messages on a timer — no scheduler to build. Reminders become configure Hermes cron + a thin ack-reset / interval-learning layer on top.

💸 Cost model

  • LLM via OpenRouter — one endpoint, both tiers
  • Conversation → capable model; memory-worthiness judgment → cheap model behind a heuristic pre-filter
  • Prepaid credits act as a natural spend ceiling (~$10–20/mo target)
  • Always-on instance = VPS compute you already pay for

🛟 Reliability — no silent failure

  • Instance under systemd/Docker restart=always — crashes self-heal
  • Dropped WhatsApp session → detected, prompts re-scan
  • healthchecks.io dead-man's-switch pings you (email/Telegram) if the box goes quiet — runs outside the VPS so it fires even when the whole instance is down
  • Your brother never has to notice — you're alerted first
